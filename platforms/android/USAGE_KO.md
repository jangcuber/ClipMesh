# Android · ClipMesh 0.3.0 사용법

## 지원 범위

**자동 백그라운드 클립보드 캡처에는 루팅과 호환되는 Vector/LSPosed가 필요합니다.** 루팅하지 않은 기기에 APK만 설치한 경우는 앱 화면이 활성화된 동안 허용되는 읽기·보내기 정도의 제한 모드이며, 완전한 백그라운드 동기화 지원으로 볼 수 없습니다.

공개 Android 빌드는 arm64-v8a용이며 설치 최소 버전은 Android 8(API 26)입니다. 이 최소 버전은 모든 제조사 펌웨어와 클립보드 후크의 호환성을 보장하지 않습니다. 모듈 로더는 classic Xposed API 82를 지원해야 합니다.

## 업데이트와 처음 설정

1. 프로젝트 릴리스에서 받은 `ClipMesh-Android.apk`(0.3.0 / 코드 6)를 설치합니다. 이 파일은 **개발용 debug 인증서로 서명**되어 있으며, 파일 이름이 바뀌어도 정식 배포 인증서가 되지는 않습니다. 기존 앱과 같은 인증서인 업데이트는 기존 앱 위에 설치합니다. 앱을 삭제하지 않으면 그룹 키와 클립보드 상태, 기기 연결 ID를 유지합니다.
2. Vector 또는 호환 LSPosed에서 ClipMesh 모듈의 **System Framework** 범위를 확인합니다. 모듈 코드가 바뀐 업데이트 뒤에는 한 번 재부팅합니다.
3. 배터리 사용은 **제한 없음**, 절전·초절전 앱 목록에서는 제외합니다. Samsung의 자동 실행 허용 항목이 있으면 허용합니다.
4. ClipMesh를 열고 기존 그룹 이름을 확인합니다. 참여할 그룹의 QR을 다른 최신 기기에서 스캔한 뒤 **동기화 켜기**를 누릅니다. 그룹 이름이 같아도 키가 다른 새 그룹을 다시 만들지는 마세요.

## Mac 없이 연결하기

새 그룹은 서버 주소 없이 만듭니다. 그룹의 QR에 기기의 공개 연결 ID를 넣어 서로 찾습니다. 이미 연결된 기기는 인증된 암호화 통신으로 다른 기기의 주소를 교환하고 기억합니다. Mac이나 임시 WebSocket 터널을 필수 허브로 두지 않습니다.

- **다른 기기에 보여줄 QR**은 먼저 이 기기의 연결 ID를 준비합니다. 처음이라면 동기화를 켜고 QR이 준비될 때까지 잠시 기다립니다.
- P2P QR에는 Mac의 임시 중계 주소를 넣지 않고 자신의 ID를 첫 번째로 넣습니다. QR에는 최대 16개 ID를 담고 나머지는 연결 후 배웁니다. 그룹에는 최대 32개 초기 연결 ID를 저장할 수 있습니다.
- 새 Android 기기는 **새 기기 연결 · QR 스캔**을 누릅니다. 카메라를 쓰기 어려우면 **QR 사진 가져오기**, 또는 **고급 설정 → 초대 링크로 직접 참여**를 사용합니다. QR 이미지나 초대 내용은 웹 QR 서비스에 올리지 않습니다.
- 기존 중계 그룹을 그대로 업그레이드하려면 **고급 설정 → P2P 자동 연결 사용**으로 연결 ID를 준비한 뒤 **Mac 없이 연결로 전환**을 누르거나, 다른 0.3.0 기기가 보여주는 새 QR에 다시 참여합니다. 그룹 키는 바꾸지 않습니다.

인터넷에서 직접 통신할 수 없으면 iroh의 암호화 중계를 사용합니다. 계정이나 Mac은 필요하지 않지만, 다른 네트워크에서 기기를 찾고 중계하는 공개 네트워크 서비스와 인터넷은 필요할 수 있습니다. 모든 외부 서버가 전혀 없는 연결을 보장하는 기능은 아닙니다.

## 한 번 켜두고 사용하기

**동기화 켜기**를 누르면 켜짐 상태를 저장하고 백그라운드 서비스를 시작합니다. 앱 화면을 닫아도 알림이 표시되는 동안 동기화합니다. 재부팅 후 첫 잠금 해제와 앱 업데이트 후에도, 켜진 상태였고 그룹이 남아 있으면 자동 재시작을 요청합니다. **동기화 끄기**를 누르면 서비스를 중지하고 꺼짐 상태를 저장하므로 재부팅 뒤에도 임의로 켜지지 않습니다.

Android의 **강제 종료**는 앱의 부팅 수신까지 막습니다. 강제 종료했거나 Samsung이 자동 실행을 막았다면 앱을 한 번 열어주세요. 화면으로 돌아왔을 때 저장된 켜짐 상태라면 서비스가 자동으로 다시 시작합니다. Android가 시작을 거부한 기록은 고급 설정에서 확인할 수 있습니다. 재부팅 전부터 잠금 해제 전까지의 동작이나 모든 ROM의 강제 종료 우회는 지원하지 않습니다.

## 상태 읽기

- **동기화 꺼짐**: 이 기기에서 송수신하지 않습니다.
- **연결 중**: 다른 기기를 찾고 있습니다. 인터넷 연결과 상대 기기의 켜짐 상태를 확인합니다.
- **기기 간 직접 연결 · 다른 기기 N대 연결 확인**: 이 기기를 제외한 인증된 기기 세션 N개를 확인했습니다. 아래에는 연결된 이름을 표시합니다.
- **인터넷 중계 연결**: 직접 연결 대신 암호화 중계를 사용합니다.
- **서버 연결 · 연결 기기 수 확인 안 됨**: 기존 WebSocket 경로입니다. 서버 연결만으로 실제 다른 기기의 수가 확인되지는 않습니다.
- **전송 모듈을 시작하지 못했습니다**: 앱을 업데이트하거나 동기화를 껐다 켜주세요. 서버 주소 없는 그룹은 잘못된 빈 WebSocket 주소로 전환하지 않고 모듈 실행을 다시 시도합니다.

## 연결과 재부팅 확인하기

1. 확인할 기기에 0.3.0 이상을 설치하고 같은 키의 QR에 참여합니다. iPhone은 지원되는 탈옥 환경이 필요하며, Android는 위의 루팅·모듈 조건이 필요합니다. 일단 함께 연결해 각 기기가 서로를 배울 시간을 줍니다.
2. 각 기기에서 다른 기기의 이름을 확인합니다. 연결 표시와 실제 복사·붙여넣기 성공은 별도로 확인합니다.
3. 한 기기를 끕니다. 예를 들어 Mac·Windows·iPhone·Android 네 기기 구성에서 Mac을 끄면 나머지 세 기기는 각각 다른 기기 2대와 통신할 수 있어야 합니다.
4. 남은 기기 사이에서, 예를 들어 Windows → Android → iPhone → Windows 순서로 서로 다른 문장과 작은 이미지를 복사·붙여넣습니다. 이미지 편집기나 메시지 작성 칸에 붙여넣으세요. 파일 경로나 공유 버튼은 **이미지 복사**와 다를 수 있습니다.
5. Android를 재부팅하고 첫 잠금 해제 뒤, 앱을 열지 않아도 ClipMesh 알림과 동기화가 돌아오는지 확인합니다. 이후 앱을 열어 기기 이름·수를 확인합니다.
6. Android에서 동기화를 끄고 다시 재부팅하면 꺼진 채로 남아야 합니다.

이 목록은 실제 기기 검증 절차입니다. 호스트 테스트와 APK 빌드만으로 특정 Galaxy의 자동 시작, 잠금·절전, 카메라, 이미지 붙여넣기 또는 Mac을 끈 세 기기의 통신이 검증됐다는 뜻은 아닙니다.

## 이미지와 진단

PNG 전송 기준 최대 8 MiB / 40 MP를 지원합니다. 지원되지 않거나 너무 큰 이미지는 전송하지 않습니다. 고급 설정의 수치는 내용 없이 캡처·수신·거부·후크 오류 횟수만 보여줍니다. QR 카메라 오류도 예외 클래스명만 남기며 이미지·QR 값·URI·스택 내용을 기록하지 않습니다.

QR과 초대 링크에는 그룹 비밀키가 들어 있습니다. 신뢰하는 기기에만 보여주세요. 공개 연결 ID 자체는 그룹 비밀키를 대신하지 않습니다.
